STUDENT

Set up your monitor

Use Windows and Google Chrome.

  1. Download and extract. Get the v0.3.4 setup package and compare its checksum below. In Downloads, right-click the ZIP, choose Extract All, then open the extracted folder showing extension and native-host.
  2. Load the Chrome extension. Open chrome://extensions, enable Developer mode, choose Load unpacked, and select the extracted extension folder inside integritest-v0.3.4. Chrome's folder picker hides files: inside extension, seeing only icons is normal. Click Select Folder while inside extension; do not select icons.
  3. Connect Windows monitoring. In File Explorer, open the extracted folder showing extension and native-host. Click the address bar, type powershell, press Enter, then run:powershell -NoProfile -ExecutionPolicy Bypass -File native-host\install.ps1 -ExtensionId amlfomdhhaklmifkneplnngkbaabibgpLook for a Registered message, then reload the extension.
  4. Pair and begin. Enter your one-time code in the extension popup, open the registered Form link shown there, then choose Start Examination.
  5. Finish clearly. Submit the Form and confirm monitoring ended. If it stays active after submission, contact your professor. For a technical problem, use Report a problem and stop early; the report marks this separately. Keep the local JSON export if delivery fails.

PROFESSOR

Prepare and review an exam

Keep each class record organized by Form.

  1. Publish a Google Form and copy its respondent viewform link. Form responses are matched separately.
  2. Create an exam record in the professor workspace using that Form link.
  3. Import a class roster with Student ID and Name columns. Assign the class to the exam and share each code privately. For a late arrival, enter a name with an optional ID; the service creates an internal ID if none is provided.
  4. Review activity under the exam record. Check each student's status, latest activity, and event counts in the monitoring table. Open a full report only when needed.
  5. Match responses separately. Match the assigned roster entry with the Google Forms response manually. A join code does not verify physical identity.

What the monitor records

Incident categories, timestamps, supported app categories, and needed website hostnames. It does not collect answers, document contents, full browsing URLs, window titles, or file paths. A contact gap shows missed communication, not what happened during it. Student monitoring requires Windows and Chrome; phone exams are outside this pilot. A join code links activity to a roster entry, not a verified person.
