# Phase 3 teacher monitoring acceptance

Use a published practice Form and a disposable class roster with **Student 1** and **Student 2**. No Student ID question is required; match responses to roster entries manually. Keep local `.dev.vars`, session credentials, join codes, and reports out of Git.

## Local setup

1. On `feat/phase3-teacher-monitoring`, run `npm.cmd install`, `npm.cmd run build:roster`, and `npm.cmd run db:local`.
2. Create ignored `.dev.vars` with a strong `TEACHER_PASSWORD`, a random `SESSION_SECRET`, and `ALLOWED_EXTENSION_IDS=amlfomdhhaklmifkneplnngkbaabibgp`. Run `npm.cmd run dev -- --ip 127.0.0.1 --port 8787`.
3. Run `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package-demo.ps1`. Check the ZIP SHA-256 against `public/downloads/integritest-v0.3.2.sha256` and the public page at `http://127.0.0.1:8787/`. Click **Check connection** on that page and verify it reports the service version.
4. In a clean Chrome profile, load `dist/integritest-v0.3.2/extension` as unpacked. Select the inner `extension` folder containing `manifest.json`, not the outer `integritest-v0.3.2` folder. Confirm its ID is `amlfomdhhaklmifkneplnngkbaabibgp`. Register the native host with `powershell -NoProfile -ExecutionPolicy Bypass -File dist/integritest-v0.3.2/native-host/install.ps1 -ExtensionId amlfomdhhaklmifkneplnngkbaabibgp`, then reload the extension.

## Student and teacher flow

1. Open `/teacher.html` in a separate browser context. Confirm the exam APIs reject an unsigned request and a wrong password. Sign in with the local password.
2. At desktop width, check the three setup pairs: import/saved classes, register/choose exam, and selected exam/add student. The cards in each pair should have equal height and the form fields should remain grouped near their labels. With at least six disposable class records, confirm five compact rows are fully visible and the rest scroll inside Saved classes; long names should shorten visually without covering Delete. Saved exams should scroll inside their card with separate, single-line rows. Tab to each list and scroll with the keyboard. At narrow width, check that the cards stack without horizontal overflow. Import an .xlsx class with Student ID and Name headers; preview it, reject blank/duplicate IDs, and verify a text ID such as 0012 stays intact. Create an exam with the published Form respondent `viewform` link, assign that class, and inspect its generated codes. Assign the same class to a second exam and confirm the codes differ. Delete the class afterward and confirm both exams keep the snapshot names. Add a late arrival by name only and another as `Name | Student ID`; check that both receive distinct one-use codes, the name-only entry shows an internal ID, and duplicate names or IDs are refused. Confirm each code is displayed once, each student appears as **Not paired**, a wrong code fails, and a used code cannot pair again. Search the exam list by title and confirm its count and results. Switch between light and dark modes on the setup and professor pages and confirm the choice persists.
3. In the student Chrome profile, pair with the assigned code. Confirm the popup shows the assigned name and ID and the registered Form link. Switch the popup between dark and light mode, close and reopen it, and confirm the choice persists. Check that pairing, delivery, desktop status, and session controls remain readable without large blank areas. Try starting on a different Form and confirm it is refused. Return to the registered Form. Open another tab in the same window and confirm a warning appears without blocking Start.
4. Start monitoring with fullscreen unchecked. Confirm the teacher view shows **ACTIVE** and a recent last-contact time. Open a webpage, ChatGPT, and a Chrome PDF; bring Word, Notepad, and Adobe Acrobat to the foreground. Check the teacher table for code state, start time, Low/Medium/High counts, latest activity, and event name. Search by a student's name or ID and filter by status; the row count and visible rows should agree. Open **View full report** and confirm a modal shows the selected student, with the highest sequence at the top. Compare IDs, sequences, categories, timestamps, and hostnames with the downloaded JSON, which remains in ascending sequence. Refresh the report manually and confirm the monitoring table still updates in the background. Close by button and Escape, and confirm focus returns to the student's report button. No answers, document contents, full URLs, or paths should appear.
5. With the Worker still running, interrupt student contact for more than 90 seconds (for example, close the student's Chrome window while keeping the professor view open in a separate browser context). Refresh the professor view and confirm **GAP** for the active session. Reopen student Chrome and the extension; confirm contact resumes and the gap clears. To test offline delivery separately, stop the Worker, record a few browser actions in the still-running student session, and confirm the popup retains them as pending. Restart the Worker and use the popup retry button or wait for its 30-second alarm. Confirm the events arrive once in order. The professor page cannot display a fresh gap while its own Worker is offline.
6. On an incomplete Form, click Submit. Required-question validation should leave the session active. Complete the Form with dummy answers and submit. Confirm the `formResponse` confirmation page is observed, the popup ends the session, and the teacher report says `FORM_SUBMISSION_OBSERVED`. Before confirmation, check that **End Examination** is disabled for a paired session. On a fresh code, use **Report a problem and stop early** for a technical failure; confirm the teacher table and JSON say `STUDENT_STOPPED_EARLY`. For a local-only session, verify ordinary manual End still works. If confirmation detection fails, record the defect and use the marked early-stop path.
7. After End, visit another page and foreground Word. Neither teacher nor local report should gain another incident. Download the service JSON in the teacher view; compare event count to the visible timeline and verify no student JSON upload is needed. Match the assigned roster entry to the Form response separately.
8. Age a disposable local session and code beyond 30 days with `wrangler d1 execute --local`, invoke `http://127.0.0.1:8787/cdn-cgi/local/scheduled`, and verify incident, session, code, and unused exam rows were removed. Never run this manipulation against real data.

## HTTPS deployment gate

After Cloudflare sign-in, create a D1 database, put its real ID in `wrangler.jsonc`, apply migrations remotely, and set `TEACHER_PASSWORD`, `SESSION_SECRET`, and `ALLOWED_EXTENSION_IDS` as Worker secrets. Deploy the Worker. Rebuild the ZIP with `scripts/package-demo.ps1 -ServiceOrigin https://YOUR_WORKER_ORIGIN`, deploy again so the setup page serves that HTTPS package, and verify its checksum.

From a separate Windows device and browser context, repeat pairing, live browser and desktop delivery, contact-gap display, reconnection, ending, service JSON download, and teacher access checks. Record the actual origin, date, device, Chrome/extension version, event count, failures, and privacy inspection in the README. Do not mark Phase 3 passed from a localhost-only view.
