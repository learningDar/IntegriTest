# Phase 2 Windows acceptance check

Use a practice Google Form with dummy text. Record the date, Windows and Chrome versions, extension ID, installed PDF reader, and pass/fail for each item. Run `node --test tests/browser.test.js tests/host.test.js` first.

1. Reload the unpacked extension at `chrome://extensions` and refresh the Form. Note its extension ID. Run `powershell -NoProfile -ExecutionPolicy Bypass -File native-host\install.ps1 -ExtensionId <extension-id>` from the repository root. Confirm the popup changes from **Desktop monitor: connecting** to **connected** after Start.
2. Start Examination on the Form. Bring Microsoft Word, Windows Notepad, and the installed supported PDF reader to the foreground one at a time. Return to Chrome between apps. Confirm one `DESKTOP_APP_ACTIVE` incident per activation with `WORD`, `NOTEPAD`, and `PDF_READER` respectively in the exported JSON. Labels must say the app became active, not that a document was read or cheating occurred.
3. Open `https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf` in Chrome. Confirm a `PDF_OPENED` browser incident with hostname `www.w3.org` and no path or PDF contents in the report.
4. While the session is active and desktop status is connected, stop only the running `ExamForegroundHost.exe` process. Confirm one `MONITORING_INTERRUPTED` incident with `WINDOWS_HOST` source. Open another webpage and confirm browser monitoring continues. Wait for the host to reconnect; verify the popup returns to connected. Repeat a supported desktop app activation and confirm it is recorded.
5. End Examination. Activate Word, Notepad, the PDF reader, and another webpage again. Confirm the incident count remains fixed after the single `EXAM_ENDED` event. Export JSON and compare the timeline count, session ID, timestamps, sources, categories, and hostname with the popup.
6. Inspect the JSON for the absence of full URLs, document/window titles, file paths, Form answers, clipboard contents, and process executable names. A generic Chrome focus loss must not be labeled as a named desktop app without a `WINDOWS_HOST` event.

If desktop status stays disconnected, check that the Chrome extension ID exactly matches `native-host/host-manifest.json` and that the current-user `Software\Google\Chrome\NativeMessagingHosts\com.learningdar.exam_monitor` registry default value points to that manifest. Relaunch the extension after correcting setup. Record any failed item as pending; automated checks alone do not pass this gate.
